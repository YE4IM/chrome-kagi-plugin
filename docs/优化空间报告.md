## 二、现状总评

热路径（每次开新标签页）已是此类插件的接近最优形态：head 阻塞式脚本解析期同步读 localStorage 镜像并 `location.replace`（先于任何绘制、不闪恢复页、不闪默认值）；镜像未命中时才由 defer 脚本走 chrome.storage 完整流程并回写镜像自愈。安全面未变：最小权限（仅 storage）、严格 CSP（connect-src 'none' 等）、URL 校验 25 组边界实测。防竞态、可访问性、双语化均已完善。

**结论：剩余空间不大。** 主要是一处 i18n 迁移遗漏（用户可见）、一处 options 页健壮性补齐，以及三个小清理。

## 三、剩余优化点（按收益/成本排序）

### P1 · 高收益低成本

**1. settings.js 三条 warning 文案未 i18n 化（i18n 迁移遗漏，用户可见）**
- 现状：settings.js:79、90、93 返回硬编码中文（"已保存的地址无效…"、"同步的地址无效…"、"暂时无法读取同步设置…"）；options.js:92 直接 `showStatus(settings.warning, …)`。英文界面用户在这三条错误路径上看到中文提示，与提交 13f8996 的"界面中英双语"目标不符。
- 建议：`loadSettings` 改返回 `warningKey`（如 `warnInvalidSaved` / `warnInvalidSync` / `warnSyncReadFail`，三条均无动态参数），_locales en/zh 各补 3 键，options.js 改 `showStatus(t(key), 'error')`；loadSettings.test.js 的文案断言随之改键名。
- 影响面：newtab.js 不消费 warning（只重定向），热路径零影响。
- 成本：约 30 行（settings.js + locales + 测试）。

### P2 · 中收益

**2. options.js 缺 HomepageSettings 加载失败兜底（与 newtab.js 不一致）**
- 现状：options.js:3 顶层解构 `const { … } = HomepageSettings;`。settings.js 加载失败（文件损坏/磁盘异常等，newtab 侧已真实发生过一次加载失败路径加固）时整个脚本 ReferenceError 中断：fieldset 保持 HTML 初始 disabled、retryBtn（HTML 初始 hidden）永不显示，页面无任何出路。
- 对照：newtab.js:5-7 已有同类兜底（提交 c6aed12），options 页漏掉了同一加固。
- 建议：将 options.js 顶层代码包进 IIFE，解构前检查 `typeof HomepageSettings === 'undefined'`，失败时 `showStatus(t('statusLoadFail'), 'error')` + `retryBtn.hidden = false` 后早退。`t()` 只依赖 chrome.i18n 不依赖该模块，兜底成立。
- 成本：约 10 行。

**3. 结论记录：loadSettings 并行读 sync 的现实现是最优权衡，勿改**
- syncEnabled=false 时也会并行发起 sync.get（Chrome 本地缓存命中，开销小），换来启用同步用户的热路径总延迟为 `max(local, sync)` 而非 `local + sync`。若改成"先读 local、按需再读 sync"，未启用同步者省一次小 IPC，但启用同步者退化为两段串行——净负收益。保持现状，防止后续误"优化"。

### P3 · 微小/可选

**4. kagi-128.png 死资源（6691 B）**
- manifest.json:21 的 128 图标用的是 kagi.png；kagi-128.png 全仓库零引用（提交 27e7b43 补图标时引入）。直接删除。

**5. 保存失败提示吞具体错误（旧 #8，仍开放）**
- options.js:130 `catch {`。建议附上真实原因：`showStatus(t('statusSaveFail') + (e?.message ? ' · ' + e.message : ''), 'error')`，sync 配额/频率/网络失败不再统一掩盖。

**6. manifest 元数据（旧 #10，仍开放）**
- 补 `author`、`homepage_url`、`version_name`；仅上架前需要。
- 另：i18n、镜像跳转、options 兜底等改动入库后版本号仍为 2.2.0，下次发布时一并 bump（流程项，非代码）。

## 四、明确不建议做的（复核维持旧结论）

- **ES modules 重构**（旧 #11）：热路径反而多一次模块解析；IIFE + 固定脚本顺序已由测试与注释锁定，收益为负。
- **newtab-redirect.js 与 settings.js 的镜像校验逻辑重复**：defer 时序限制下的故意重复（redirect 必须先于 defer 执行、无法复用模块），homepageMirror.test.js 已锁定两侧规则一致。不要"优化"掉。
- **后台 SW 预重定向 / 真实站点 favicon / 构建打包工具链**：维持旧报告否决（权限面变大、隐私倒退、25KB 无依赖代码库上工具链是负收益）。
